# Transaction

## 정의
- 트랜잭션은 데이터베이스의 상태를 변화시키기 위해서 수행하는 _논리적인 단위_
- 여러개의 sql문을 묶어 모두 성공하거나 , 아니면 수행하지 않은 상태로 처리한다.
- sql문 수준의 함수/ 메서드와 비슷하다.

## 트랜잭션의 특성
1. 원자성 : 트랜잭션 내 작업은 모두 반영되거나 모두 취소되어야 함.
2. 일관성(consistency) : 트랜잭션 완류 후 DB는 항상 미리 정의된 제약 조건 준수
3. 격리성?(Isolatiion) : 실행 중인 트랜잭션은 다른 트랜잭션의 간섭을 받지 않는다.
4. 지속성, 영속성(durability) : 트랜잭션 결과는 오류가 발생해도 영구적으로 저장

## 트랜잭션 제어어 (TCL)
1. `START TRANSACTION` : 트랜잭션의 시작
2. `COMMIT` : 모든 작업이 정상일 때, 변경 내용을 실제 DB에 영구 저장
3. `ROLLBACK` : 작업 오류 발생시, `START TRANSACTION` 직전 상태로 복구

```sql
-- INSERT INTO products VALUES ('iPhone18proMax',10);

-- 성공 
START TRANSACTION;

-- 주문 접수
INSERT INTO orders(product_name,quantity) VALUES ('iPhone18proMax', 2);

-- 재고 차감
UPDATE products 
SET stock = stock - 2
WHERE product_name = 'iPhone18proMax';

COMMIT;

-- 실패 사례
START TRANSACTION
-- products에 없는걸 주문
INSERT INTO orders (product_name, quantity) VALUES ('GalaxyS26Ultra',1);

UPDATE products SET stock = stock - 1
WHERE product_name = 'GalaxyS26Ultra';

ROLLBACK;
```

- 재고가 음수값이라면? 같은 문제가 db에 남아있다.

```sql
start transaction;

select * from products 
where stock < 0;

commit;
```

위는 음수인거 확인되면 성공이라는 뜻

```sql
start transaction;

select * from products 
where stock < 0;

rollback;
```

위는 음수라면 롤백 하겠다는 뜻<br>

그렇다면 orders관련한 부분의 트랜잭션 내부에서 다시 트랜잭션을 재정의해야한다는 것을 의미

# Trigger
## 정의
- 테이블에 insert, update, delete와 같은 이벤트가 발생했을 때 데이터베이스가 자동으로 실행하도록 설정된 sql블록.
- 활용사례
    - 주문 재고 시 자동 차감(데이터 연동)
    - 데이터 변경 시 로그 기록(감사 및 기록)
    - 특정 조건 미달 시 데이터 입력차단(무결성 강화)

## 트랜잭션과의 차이점
- 둘 다 데이터의 무결성을 지키기 위한 것이라는 공통점을 가지지만, 작동하는 방식과 주체에서의 차이가 존재한다.

### TRANSACTION
- 핵심 성격 : 논리적 작업 단위(묶음 처리)
- 실행 주체 : 개발자
- 작동 시점 : `start`, `commit` 시점
- 주요 목적 : 데이터의 안전한 일괄 처리

### TRIGGER
- 핵심 성격 : 이벤트 반응
- 실행 주체 : DBMS가 자동으로 실행
- 작동 시점 : `insert/update/delete` 발생 시
- 주요 목적 : 데이터 간의 자동 연동 및 기록
- DB에 미리 정의해놓고 누군가가 orders에 대고 데이터를 집어넣었네?(외부에서 나에게 주문을 넣었다면)<br>
-> DB가 감시하고 있다가 products 테이블에 재고 빼는거 실행함<br>
-> 음수네?<br>
-> '재고가 부족합니다'를 출력해야겠다<br>
식으로 정의된 대로 실행

## 정리를 하자면
**트리거는 트랜잭션의 일부**에 해당한다. insert를 할 때 트리거가 발동돼서 재고를 깎는데 오류가 나면 insert를 포함한 전체 트랜잭션이 실패한다. 즉, 트리거도 트랜잭션의 원자성을 따른다고 해석할 수 있다.

- 그래서 여기서 더 발전하면 stored Procedure / function 개념은 있지만 JPA에서 안다룰거고 sqld에 없다면 있다는것만 알아둬라
